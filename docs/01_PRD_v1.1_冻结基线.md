## 1. 产品定位与目标

本产品是一款以 **Q 版 2D 桌面角色 + AI 智能陪伴 + 长期记忆与关系成长 + 自主行为模拟** 为核心的 macOS 桌宠。角色应以自然、不打扰为第一交互原则，在桌面上活动，支持文字输入和语音回复，并能逐步发展成多角色虚拟生态。

**产品目标**
1. 在 macOS 上提供稳定、轻量、可拖拽、可互动的透明桌面角色。
2. 支持可配置 AI 对话、长期记忆、情绪/关系成长，形成连贯的陪伴体验。
3. 角色素材、模型和 TTS 服务可替换，数据可控、可备份、可迁移。
4. 最终支持丰富动作、多角色共存、角色社交、情境化自主行为。
5. 每一阶段均可运行、可测试、可验收，防止只有 UI 或占位逻辑的“假完成”。

**当前非目标**
- V1.0 不要求语音输入、唤醒词、实时双向语音（第 7 题明确选择文字输入 + 语音回复）。
- V1.0 不要求电脑自动化操作、文件代理执行或持续截图/录音。
- Windows 为后续扩展目标，**不计入 V2.0 必须验收的交付范围**。
- 不要求强制账号注册，也不要求自建在线同步服务。
- 不在技术验证前承诺某一渲染引擎、固定的内存上限或所有第三方窗口攀爬兼容。

## 4. 功能需求与验收要点

### FR-A 桌面角色和运行引擎
1. macOS 透明角色窗口与非透明 UI 分离；支持角色拖拽、缩放、显示/隐藏、菜单栏入口与主动退出。
2. 支持角色运动、待机、基础落地与屏幕边界限制；空白区域尽量不拦截其他应用鼠标输入。不同系统版本必须原型实测，不能承诺全场景透明像素精准穿透。
3. 采用事件驱动的动作状态机，支持循环、单次、优先级、打断、超时回退、镜像/方向与异常降级。
4. 普通工作、全屏、闲置、低电量或高负载情况下可降低动画负载；有手动勿扰、暂停和立即隐藏入口。
5. 验收：可在实际 Mac 桌面上完成交互，退出可释放资源，不得以录屏演示或静态截图取代运行验证。

### FR-B AI 聊天、人格及记忆
1. 文字输入为必需，模型输出支持文本气泡及完整聊天窗口；与第 7 题一致，**无需语音输入**。
2. 支持多个云端聊天模型的 API Key、端点/模型配置、连通性测试和手动切换；密钥在安全存储中维护。
3. 基础人格、关系成长、情绪状态互相关联，但应由规则和记录驱动，不宣称模型具有真实感情。
4. 记忆层级：当前会话、用户事实与偏好、角色关系、关键事件；每条长期记忆具有来源、更新时间、适用角色和可管理状态。
5. 用户可以查看、纠正、删除记忆；可以使用私密会话模式阻止持久化及记忆写入。
6. 默认不向 AI 发送全部历史：采用受控上下文组装，必要记忆可预览；切换模型不清空历史。
7. 验收：软件重启后同角色对话和授权记忆可恢复；删除记忆后后续上下文不会继续引用已删内容。

### FR-C 语音回复与动画联动
1. 用户打字，桌宠通过可配置的 TTS 服务生成自然语音；支持语音开关、音量、语速、试听和独立角色音色。
2. 角色说话时播放简单口型、眨眼或表情；初期可通过音频播放/振幅驱动，并不要求完整音素级唇形。
3. 云端 TTS 不可用时要能退化为文字显示，不能卡死角色引擎；未来可增加本地引擎及合规自定义音色。
4. 每次云端调用必须有超时、取消、错误反馈和基础费用记录；避免后台无限重试。

### FR-D 情绪、自主生活、多角色
1. 角色状态：心情、精力、熟悉度及作息，影响动画、主动交互与言语风格；成长不应惩罚用户长时间未启动软件。
2. 使用时间、互动频率、用户授权的活跃应用/系统空闲信号决定主动互动频率；支持一键勿扰。
3. 日常活动包括读书、休息、玩耍、发呆等；天气感知需明确城市/位置授权，不应默认采集精确定位。
4. V1.5 起支持多个独立角色 ID、外观 ID、声音配置与记忆域，多角色共存；换肤不重置角色关系。
5. V2.0 目标为角色之间自主活动和社交，日常预设互动尽量不调用大模型；AI 互聊应限制轮数、并发、频率与预算。

### FR-E 开放角色与动画资源
1. 标准角色包包含 `manifest.json`（或等效声明）、角色预览、PNG/Sprite Sheet、动画元数据、外观/语音/人格的可选配置。
2. 角色包导入时校验格式、素材路径、尺寸/透明通道、动画帧、名称冲突及资源上限；拒绝可执行脚本、目录穿越及不受信任的远程资源加载。
3. 单一角色身份可以绑定多个外观；V1.5 再支持相容的分层换装、骨骼动画驱动。
4. 最终动作库目标 30 类以上，统计口径为可真实播放且能被事件触发的**动作类别**，不把单纯改名、静态图和重复动作算作新增。

### FR-F 界面与管理
1. 平时以桌宠主体和简洁气泡为主；双击或快捷键进入聊天，独立管理中心集中管理角色、记忆、模型、声音、动画、数据和隐私。
2. 完整聊天窗口支持历史查看、复制、搜索、语音重播、管理角色会话；高级主题、字体、透明度、布局自定义在后续阶段完善。
3. 重要操作（删除数据、导入覆盖、升级回滚）需二次确认，并显示结果与错误原因。

### FR-G 数据、安全和备份
1. 聊天、角色、记忆、关系、设置本地优先保存；数据库版本迁移应可追踪、可回退到事先备份的完整状态。
2. API Key 使用操作系统安全存储，默认不写入日志、明文配置、角色包或一般备份。
3. 基础能力在离线状态可用；云端 AI 与 TTS 故障须降级而不丢本地数据。
4. 权限请求遵循最小必要原则，默认不截屏、不录音、不记录键盘内容；可撤销应用级授权并引导到系统权限设置。
5. V1.0 具备完整/按角色导出、定期备份、校验、恢复演练、加密备份与本地路径设置；不能声称“已经备份”而未校验或抽样恢复。
6. 隐私聊天不得写入永久聊天历史或长期记忆；日志在脱敏后保留必要的可诊断信息。

## 6. 性能、兼容及质量原则

- **目标主机（拟）**：Mac mini M2 16GB；补充 Intel MacBook Pro（具体系统版本与硬件配置需在执行时记录）。
- **V1.0 初始参考目标（待 V0.0 校准）**：冷启动至可交互约 5 秒以内；单角色普通状态 30 FPS；空闲内存参考值不高于 250 MB；待机 CPU 目标低于单核心 5%；连续运行至少 24 小时。
- 上述数字目前是**研发参考目标，不是已验证性能或不可调整的硬性门槛**。应定义采样工具、负载场景和计算口径，在 V0.0 报告中确认。
- 必须提供功能测试、自动化回归、性能记录、长时运行、断网/API 超时、升级与备份恢复试验的实际证据；缺测试不等于通过。
- 对 macOS 全屏 Spaces、多屏、窗口攀爬等敏感行为，应给出兼容矩阵和退化策略；不可把系统限制表述为已实现能力。

## 10. 第 34 轮审计修订（规范性增补，优先于前文中不够精确的表述）

1. **技术选型不预设胜者**：先在同一设备、同一素材、同一测试场景比较至少两条技术路径。Tauri 透明 WebView 是否使用 macOS 私有 API 必须记录，不能隐瞒分发风险。
2. **空白像素穿透的验收分级**：将整窗穿透、角色可点击与透明区域精确穿透分开测试。若仅能整窗穿透，T02 只能 PARTIAL；不得用“可以设置忽略鼠标事件”替代角色交互的证据。
3. **角色素材与代码分开记功**：动作完成 = 原始素材存在 + 可解码加载 + 多帧播放 + 事件触发 + 中断/恢复验证；仅动画名称或展示图，不得计算完成。
4. **隐私与数据在使用前落实**：任何实装聊天/记忆的阶段必须先验证 API Key 安全存储、持久化隔离、删除/私密会话和基础传输/日志脱敏；不可等正式版才补。
5. **多角色间隔离**：角色 ID 与皮肤/服装 ID 独立；更换皮肤不清除记忆，换角色不得泄露别的角色的私有记录。
6. **费用阀门**：每次云端调用有超时、可取消、速率/次数限制和预算预警；仅在数据来源可信时展示成本估算，不得承诺绝对消费金额。
7. **性能比较口径**：每候选同分辨率、同窗口尺寸、同帧数、同物理负载，记录 P50/P95 帧时，内存常驻/峰值，CPU 统计方法和机器信息；没有实测标 N/A。
