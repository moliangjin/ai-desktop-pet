# 03｜验收与审计规范（V0.0～V2.0）

版本：1.1｜2026-10-12｜研发方：MiniMax｜需求状态：冻结｜开发授权：仅 V0.0

## A. 状态定义

- `PASS`：所有本阶段硬门槛完成、有可核查的本机/构建/运行证据，无阻断缺陷。
- `PARTIAL`：功能部分完成、存在未测项、真机缺失或尚有阻断待复验。
- `FAIL`：出现技术不可行或安全/数据重大违约，或核心场景无法运行。
- `NOT_TESTED`：环境不支持/权限未授予/未实施，绝不能算作 PASS。
- 若只在 CI 通过单元测试，真实桌面交互项不得宣称 PASS。
- 所有功能交付证据按 `实现代码 + 运行产物 + 操作步骤 + 观察结果 + 日志/测试记录` 提交。

## B. 质量门槛

| 阶段 | 核心硬门槛 | 故障/安全门槛 | 输出 |
|---|---|---|---|
| V0.0 | 至少两技术原型可比较；T01～T10 分类与测试证据 | 未授权权限请求/高风险方案硬否决 | 选型 RFC、性能基线、原型、报告 |
| V0.1 | 单角色可拖拽/真实四类动作；透明/非透明窗口协调 | 即使素材缺失也可退出、不丢用户设置 | 可运行开发构建、回归脚本 |
| V0.5 | 真正文本 AI 调用/TTS/历史/记忆增删恢复（用户同意接入后） | Key 不落明文/日志；断网降级；私密会话不保存 | 接口测试、恢复案例、隐私检查 |
| V1.0 | 人格成长/适度主动/基本生活/设置/备份可用 | 至少 24h 运行、灾难恢复、更新兼容 | 个人日常正式版、完整测试 |
| V1.5 | 角色包导入/换装/至少两角色同屏 | 记忆隔离/素材包防目录穿越/资源泄漏检测 | 角色包规范、导入验收 |
| V2.0 | 30+ 非重复实动作/复杂环境互动/角色社交 | 并发和费用限制、长期多角色稳定性 | 逐动作验收表/兼容矩阵 |

## C. 性能统计规则

1. 标明精确设备型号、芯片、内存、macOS 版本、屏幕分辨率和缩放、负载应用、构建 hash。
2. 冷启动：从进程启动至第一帧可交互；至少五次启动，报告 P50/P95，首次依赖安装时间另计。
3. 内存：RSS 或系统认可的驻留指标，标清单位 MB/MiB；典型值、峰值区分；不能混用活动监视器与别的统计定义。
4. CPU：标注监视工具、采样间隔和百分比口径（单逻辑核心 100% 还是整机 100%）。
5. FPS：以 30 FPS 为参考目标，记录实际 FPS 及帧间隔 P50/P95；同候选用同一参数与动作循环。
6. 每个候选测冷启动、10 分钟交互、30 分钟持续运动、10 分钟空闲、20 次关闭重启；无法执行时标 N/A 与原因。
7. Photoshop 场景实际验证如果无软件/权限，只记 NOT_TESTED；不得拿一般文本编辑器冒充。
8. V1.0 参考值：启动 ≤5s、正常动画 ≥30FPS、单角色典型空闲 RSS ≤250MB、CPU 低于单核心 5%、24h 稳定；由 V0.0 数据校准后提交用户批准方可变为硬门槛。

## D. 数据与安全规则

- Git 仓库只能包含测试数据，禁止真实 API Key、聊天隐私、钥匙串导出、个人 Mac 用户目录、真实定位等。
- 安装构建必须声明：签名/公证状态、最低系统版本、目标架构、所需权限。
- 构建前清楚列出将更改的文件；对已存在仓库先检查 git status，禁止覆盖未提交更改。
- 不能因为研发环境缺 GUI 就通过模拟截图宣称真实 macOS 交互 PASS。
- 升级、数据库迁移、清理程序前均需可恢复快照；任何真实用户数据迁移需单独授权。
- 禁止自动发布公开仓库、上传私密素材、注册付费服务、启用系统级监控或请求不必要权限。

## E. 文档与阶段备份标准

`README.md`、`CHANGELOG.md`、`KNOWN_ISSUES.md`、`HANDOVER.md`、`TEST_EVIDENCE_MATRIX.csv`、`PERFORMANCE_RAW.csv`、`TECH_DECISION.md`、`V0_0_FINAL_REPORT.md` 至少在 V0.0 阶段存在。

备份包含源代码、依赖锁文件、素材许可证、测试记录；排除 `.git` 之外的个人机密数据、构建缓存及密钥。备份 SHA256 + 文件数量；对压缩包做打开/解压校验；恢复于独立临时目录并能重新构建（若环境具备工具）。Git tag 与备份 manifest 对齐。

## F. 进度口径

总阶段权重：`V0.0=10%`, `V0.1=15%`, `V0.5=20%`, `V1.0=25%`, `V1.5=15%`, `V2.0=15%`；总进度只有正式 PASS 且已封版阶段才增加相应权重。

阶段内部以通过测试用例数/全部可适用用例数显示完成比例，另独立列出 NOT_TESTED 数量；测试用例发生变化时重新核算。中间进度仅表示阶段内覆盖，不得虚报总进度。
