### 2.3 透明化技术要点（已验证的踩坑记录）

**坑**：角色白色实验服（#F5F8FA）与白背景在亮度上无法用全局阈值区分。直接按「近白即透明」会把衣服抠穿。

**正确做法**（`build_master_and_previews.py::to_rgba`）：从画布四边做 **flood fill（BFS）**，只删除「与画布边缘连通」的白色区域。被深色描边包围的白色制服自然保留。

**禁止**：任何形式的「按亮度阈值全局置 alpha=0」。

## 四、锚点与姿态（R122 §五 2）

> 「目前 R119 参考锚点为 (0.5, 0.9)。这只是待验证设计参数，不应直接认定适合全部动作。」

### 4.1 各姿态锚点规范

| 姿态 | 锚点 x | 锚点 y | 依据 |
|---|---|---|---|
| 站姿（idle / walk / run / turn） | 0.5 | **0.90** | 脚底中心；与 R113 `renderer.js:327` 一致 |
| 行走（walk） | 0.5 | **0.90** | 同站姿，双脚交替但支撑脚底不变 |
| 坐姿（sit_rest） | 0.5 | **0.86** | 坐姿下最低接触点是臀部/腿侧，需上移 4% |
| 躺下睡觉（lie_down） | 0.5 | **0.78** | 躺姿最低点是侧身/头肩，需上移 12% |

### 4.2 避免动作切换时角色跳位置

**规则**：所有姿态的锚点必须落在**「角色与地面的实际接触点」**上，而不是笼统用 0.90。

具体做法：

```
屏幕位置计算：
  screen_y = ground_y - sprite.height * anchor_y

  ground_y 为桌宠的「站立地面线」
  idle   : anchor_y = 0.90  →  脚底贴地
  sit    : anchor_y = 0.86  →  臀部落地点贴地（比脚底低 4% 是坐姿的自然结果）
  lie    : anchor_y = 0.78  →  肩/侧身贴地
```

**过渡规则**：动作切换时用 150–250 ms 的 `ground_y` 缓动插值，**不做瞬时跳变**。

### 4.3 阴影跟随规则

| 姿态 | 阴影形态 | 说明 |
|---|---|---|
| 站姿 / 行走 | 脚底椭圆，宽度随支撑腿摆动 ±8 % | 行走时阴影随重心左右微移 |
| 跑步 | 阴影略拉长 + 轻微模糊 | 腾空帧阴影缩小、透明度降低 |
| 坐姿 | 臀下椭圆，更宽更扁 | 宽度约 1.4 × 站姿 |
| 躺姿 | 长条椭圆，长轴与身体垂直 | 长度约 1.8 × 站姿宽度 |
| 跳跃 | 阴影与身体分离，高度随 y 变化，尺寸随高度缩小 | 腾空越高阴影越小越淡 |

**阴影实现**：建议由**程序生成**（椭圆 + 径向渐变纹理），不作为美术素材逐帧绘制。这样可随姿态参数化变形，成本极低。

### 4.4 与 R113 的兼容性

R113 `renderer.js` 已使用 `anchor.set(0.5, 0.9)`。本规范：
- **站姿锚点与现有代码完全一致** → 站姿/行走/跑步无需改动
- 坐姿/躺姿锚点不同 → R0.5+ 需在动画播放器中按动作读取 `anchor_y`，属于**新增功能**，不影响 C2 拖拽底层

## 五、动画制作路线（R122 §五 4）

> 「注意 PixiJS 当前为 7.4.3，不得未经技术验证就声称任意版本 Spine 运行时能够直接兼容。」

### 5.1 三条路线对比

| 路线 | 制作成本 | 运行开销 | 表达力 | 与 R113 兼容性 | 本项目适配度 |
|---|---|---|---|---|---|
| **A. PNG 序列帧** | 低（逐帧画） | 低（PixiJS 原生支持） | 有限（只能做已有帧） | ✅ 完全兼容，`PIXI.Assets.load` 直接用 | ⭐⭐⭐⭐⭐ |
| **B. 骨骼动画（Spine）** | 高（需绑定+建骨+K 帧） | 中（需 `@pixi-spine` 运行时） | 高 | ⚠️ **需验证** | ⭐⭐ |
| **C. 混合** | 中 | 中 | 高 | ⚠️ 骨骼部分同上 | ⭐⭐⭐ |

### 5.2 Spine 兼容性技术核验（不夸大）

**已知事实**：
- R113 使用 `pixi.js ^7.4.0`
- Spine 官方维护 `@pixi-spine/all-4.x` 等版本化包，与 PixiJS 7.x 对应
- **本轮未安装、未测试任何 Spine 运行时**

**本轮结论（严格表述）**：

> **首批 GATE 3 样片一律使用 PNG 序列帧，不引入 Spine。**
>
> 理由：
> 1. Spine 运行时兼容性在本轮**未经验证**，按 R122 要求不得声称可用
> 2. 15 类基础动作中，绝大多数（呼吸/眨眼/行走/停步/坐下/睡觉等）用序列帧完全够用
> 3. 序列帧生产速度快、调试直观、美术门槛低
> 4. 若 GATE 4 批量生产后确实需要骨骼（如衣服/头发的物理摆动），**在 GATE 4 之后**单独评估并做兼容性测试

### 5.3 逐动作制作方式建议

| 动作 | 推荐方式 | 理由 |
|---|---|---|
| 待机呼吸 idle | PNG 序列帧（4–6 帧循环） | 幅度小，帧数少 |
| 左右行走 walk | PNG 序列帧（6–8 帧循环） | 腿部摆动规整 |
| 跑动 run | PNG 序列帧（6–8 帧循环） | 同上 |
| 停步 stop | PNG 序列帧（2–3 帧一次性） | 极简 |
| 转身 turn | PNG 序列帧（4 帧：右向 2 帧 + 左向 2 帧） | 靠左右向素材切换，无需骨骼 |
| 坐下 sit_down | PNG 序列帧（4–6 帧一次性） | 姿态变化但帧数可控 |
| 睡觉 lie_down | PNG 序列帧（6 帧：躺下 3 + 静止 3） | — |
| 起身 wake_up | PNG 序列帧（4–6 帧一次性） | — |
| 跳跃 jump | PNG 序列帧（4 帧：蹲 1 + 腾空 2 + 落 1） | — |
| 点击反应 click_react | PNG 序列帧（2–3 帧） | 极简 |
| 拖拽反应 drag_react | PNG 序列帧（2 帧） | 极简 |
| **伸懒腰** stretch | PNG 序列帧（6 帧） | 上肢大幅拉伸，序列帧可表现 |
| **四处张望** look_around | PNG 序列帧（4 帧） | 头部转动可用左右向头部素材 |
| **眨眼** blink | **分层切换**（眼部独立图层，3 帧） | 纯图层切换，不需重绘全身 |

### 5.4 「必须重新绘制」vs「可用少量帧或分层」

按 R122 §五 4 要求分类：

**可用分层/切换实现（低成本）**：
- 眨眼（眼部图层切换）
- 表情变化（6 种表情已在 A5 产出）
- 左右翻转（同一套素材镜像，**禁止用 `scale.x=-1`**，会反向高光；应在导出时生成镜像帧）

**必须逐帧重绘（中高成本）**：
- 行走 / 跑步（腿部姿态变化）
- 坐下 / 躺下 / 起身（大姿态变化）
- 伸懒腰 / 跳跃（大幅度肢体动作）

## 六、左右翻转规则（R119 §六 3 延续）

| 项 | 规则 |
|---|---|
| **禁止** | 运行时使用 `sprite.scale.x = -1` 翻转 |
| 原因 | 会导致高光/阴影方向反转、光源不一致，视觉上明显错误 |
| **正确做法** | 在素材导出阶段生成左右两套（或左向 + 镜像导出为右向），运行时切换纹理 |
| 锚点 | 翻转后 anchor.x 仍为 0.5（对称） |
| 光影方向 | **不随翻转改变**。R119 规范：默认光源 45° 左上 → 右下，所有动作、所有朝向保持一致 |
