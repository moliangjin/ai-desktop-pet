## 1. 四条用户反馈 → 根因 → 修复 → 证据

### 1.1 "启动时莫名抬手，点击后也重复手放胸前的动作"

**根因（实测，非推测）**：R138 的 `idle_04` **不是眨眼帧**，它是"右手横在胸前"的姿势。R147 的眨眼序列 `[4,5]` 与点击反馈都用了它 → 站立时每 1.6~3.4s 抽手到胸前一次；点击反馈 620ms 也全靠这帧。

> 放大确认图：`assets/character_R138/idle/idle_04_blink_half.png`（手臂横在胸前）。

**修复**
| 项 | 改前 | 改后 |
|---|---|---|
| `idle.director.blink_sequence` | `[4, 5]` | `[5]`（纯闭眼、手臂下垂） |
| `idle.director.excluded_frames` | `[1, 2, 3]` | `[1, 2, 3, 4]`（帧 4 永不播放） |
| 点击反馈 | 眨眼式反馈（用 idle_04/05） | **歪头 + 眯眼笑**（R153 烘焙的 `happy` 帧）+ 7px 轻微弹跳 |

**客观证据**
- 真实运行日志：`IDLE_BLINK frame=5` 出现 2 次，**`frame=4` 出现 0 次**（e2e `TD5`）
- 像素级：点击反馈段头部**虹膜像素 min = 9**，睁眼待机 min = 90 —— 证明点击时眼睛确实是闭着的（"眯眼笑"），而不是抬手（e2e `TH5`）
- 运行时日志：`R153 CLICK_REACTION start (歪头眯眼笑) duration=780ms bump=7px`

### 1.2 "坐下后瞬间变成躺姿，过渡非常生硬"

**根因（实测）**：`sleep_enter` 的**第 0 帧本身就是坐姿**（`sleep_enter_01_sit`）。所以最初做的**动作级**溶解 `sit_rest → sleep_enter` 实际是"坐 → 坐"，肉眼完全看不出变化；真正的躺姿出现在**动画换帧那一瞬**，是硬切 → 用户看到的仍然是"瞬间躺下"。

> 这条是本轮**第一版修复没修对、被自己的运行时采集证伪**的地方：动作级溶解的日志在打（`BLEND sit_rest -> sleep_enter (320ms)`），但逐帧混合度测量显示 `f00→f10` 全是纯坐姿、`f11` 一帧直接跳到纯躺姿。

**修复**：新增**帧级**交叉溶解 —— 一次性动画**内部**换帧也走渐变。

| 动作 | 帧级溶解 |
|---|---|
| `sleep_enter`（坐→躺） | 320ms |
| `wake_up`（躺→坐起→站） | 280ms |
| `head_nod`（点头→回位） | 180ms |
| `blink_soft` | 0（眼睛不做溶解，会糊） |

**客观证据**
- 坐→躺之间实测 **7 帧中间态**：`d_sit` 21.6 → 42.7 递增、`d_lie` 78.6 → 37.9 递减（`d_sit`/`d_lie` = 该帧与纯坐姿/纯躺姿的平均像素差）
- 运行时日志：`R153 FRAME_BLEND sleep_enter 0 -> 1 (320ms)`
- 逐帧帧条：`evidence_r153_gifs/R153_sit_to_lie_transition.png`（#8–#10 纯坐 → #11–#15 溶解混合 → #16–#17 纯躺）

### 1.3 "行走时身体明显前倾，像要摔倒"

**根因（实测）**：R147 的**整体水平错切** `skew_x`（`walk_left +0.085` / `walk_right -0.11`）—— 整个身体偏离垂直轴，上半身整体偏移约 0.09 个身高（5.33°）。方向表达其实**已经不需要靠剪切**：R148 用派生镜像帧把"落地脚/鞋尖朝哪边"修对了，剪切只剩副作用。

**修复**：`walk_left.lean.skew_x = 0.0`、`walk_right.lean.skew_x = 0.0`（方向元数据 `direction = ∓1` 保留）。

**客观证据（两套独立实现互验）**

## 3. 自主行为有哪些实际改善

**改前**：引擎是 `IDLE → (30% 睡 / 70% 走)` 二选一，走完就睡，睡醒再走。用户在真机上看到的就是"走 → 停 → 睡 → 醒"的机械循环。

**改后**（`src/behavior_engine.js`）

| 维度 | 改后 |
|---|---|
| 活动池 | **5 类加权**：站立小动作 0.46 / 散步 0.62 / 坐下休息 0.22 / 困倦打盹 0.22 / 躺下长睡 **0.10**（原 0.30） |
| 不重复 | 连续做同类活动权重打 **0.25 折**（单测 `T14` 用"有折扣 vs 无折扣"同随机流对照证明折扣确实生效） |
| 醒后冷却 | 醒来 **45s 内不再触发睡眠**（单测 `T16`） |
| 打盹 vs 长睡 | `DOZE`（坐着，7~15s）**不等于** `SLEEP_ENTER`（躺下，20~45s）；单测 `T15` 断言打盹全程不进 `SLEEP_ENTER`/`SLEEP_LOOP` |
| 睡眠期间 | 主循环 = **躺姿呼吸**（胸口微起伏），每 7~15s 插入一次"换睡姿"微调（4.2s）再换回呼吸（单测 `T17`）—— 取代原来 700ms 一换、3 个睡姿差异 82% 的"抽动" |
| 醒来收尾 | `wake_up` 播完 → **伸懒腰** → 回站立（单测 `T6`） |
| 站立小动作 | 5 项加权池（张望/歪头/点头/伸展/开心），**不重复上一次**（单测 `E1`） |

**运行时量化**（真实采集帧，e2e `TH3`）：5 个多帧库动作的"变化像素数" = 张望 2698 / 歪头 3040 / 点头 8934 / 眨眼 8799 / 呼吸 1705 —— **没有一个是静止的**。

**呼吸幅度调优**：第一版呼吸幅度 0.022 在 200×240 窗口里换算只有 **1.4px**，等于"看不到变化"（正是用户说的"睡眠持续时间长，几乎没有变化"）。改为 0.045/-0.030 → 屏上约 **3px**（身高的 1.2%），肉眼可辨但不失真（e2e `TH6`：起伏可见且远小于 2% 门槛）。

## 6. 本轮额外修掉的两个 bug（比用户反馈更严重）

### 6.1 `anim_clock` 的每帧时长数组 bug —— **所有多帧新动作在运行时全是静止的**

- **现象**：真实运行采集显示 `look_around` / `tilt_head` / `head_nod` / `blink_soft` / `sleep_breath` 的**帧间差全为 0.000** —— 5 个新动作全是定格。
- **根因**：`src/anim_clock.js` 的 `period()` 直接 `return m.frame_ms`；而库动作用**每帧时长数组**（如 `blink_soft [130,170]`）→ 数组参与数值比较被转成 `NaN` → `now - lastAdvanceAt >= NaN` 恒为 false → **帧永远不推进**。核心动作用标量 `frame_ms`，所以这个坑此前从未被触发。
- **为什么单测没抓到**：R153 的单测验的是 manifest 配置与烘焙产物，**没有一条测试真的用数组 `frame_ms` 驱动 `AnimationClock`**。
- **修复**：`period(meta, frameIndex)` 支持数组；一次性动画的"末帧保持时长"也改用末帧自己的时长。
- **回归防线**：`tests/r153_action_library.test.js` 的 **J1 / J2 / J3**（数组推进、数组一次性完成回报、标量行为不变）。
- **修复后实测**：各动作"变化像素数" 1705~8951，全部在动。

### 6.2 帧级溶解缺失（见 §1.2）

动作级溶解看起来生效（日志在打），但因为 `sleep_enter` 第 0 帧就是坐姿，真正的姿态跳变在换帧那瞬 —— **日志 PASS 而视觉 FAIL**。这也是本轮坚持"用采集帧的逐帧混合度测量而不是看日志"的原因。
