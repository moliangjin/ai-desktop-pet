## 2. 素材可行性评估（本轮第一交付物，结论推翻了前两轮）

### 2.1 结论一：「R138 无手部素材」是**错的**

R153 `bake_report` 与 R156 报告都写着「R138 无手部素材」，并据此把比心/鼓掌/挥手全部降级成「近似」或列入 `NEEDS_NEW_ASSETS`。

**实测事实**：

- `assets/character_R138/idle/idle_00_base.png` 里**两只手都是张开的、5 指带描边**，像素完整。
- R138 自己的切层脚本 `图文工作/character_animation_R138/03_LAYERS/split_a1_layers.py` **漏切了画面左臂**：`LAYERS.json` 只登记了 `head / torso / leg_r / arm_r` 4 层，而 `arm_r` 是**胸前那个拳头**（R153 当年正是因为这个把 `idle_04` 从眨眼序列里踢掉）。
- 所以「没切出手」被误读成「没有手」。

**真正缺的不是手，是「能把手臂摆到别的位置」的技术** → 本轮自建手臂骨架补上。

### 2.2 结论二：全仓库只有**正面**素材，真转身做不到

逐目录核查 `assets/character_R138/`、`character_R141/`、`character_R153/`、`character_R156/` 及 R138 母版工程 `图文工作/character_animation_R138/`：**没有任何侧身 3/4 视图或背面视图**。

- i2i 三/四视角在 **R130 已连续三次失败**（身份漂移 / 姿态漂移），且本轮禁止充值。

⇒ **本轮下架 `cheer_spin`，不做伪转身**，改为输出精确的新素材需求清单（§7）。

## 3. 手臂骨架技术（`36_R158_arm_rig.py`）

不重画角色、不改脸、不改配色、不引外部素材、不做 i2i。

1. **干净切层**：描边暗线当阻隔做洪水填充 ⇒ 拿到连通��「袖 + 袖口 + 手」区域。
   - 洪水填充会把**暗色描边当阻隔** ⇒ 手臂/手的描边不在掩膜内，摘除后会留虚线鬼影 ⇒ 单独扩一圈（`dilate 4`）补切手部描边与手指，**手部掩膜覆盖率 1138 → 2440 px（+114%）**。
2. **圆形咬口**：肩/肘/腕各切一个圆盘（半径 26 / 17 / 15）。**每段只带自己「近端关节」的完整圆盘，不带远端关节的圆盘** —— 圆盘绕自身圆心旋转后仍与原位重合 ⇒ **关节处永不出现缝隙**。
3. **三关节链 + 两骨 IK**：肩 → 肘 → 腕 → 手，用 IK 求「手要到哪里」的关节角。
4. **衣身还原**：摘掉袖子后把被盖住的衣身补回来 —— 擦除区 = 手臂掩膜 ∪ 外圈描边（**只擦袖子自己外/内轮廓，不误擦大褂下摆**），再按行重建大褂边缘（描边 2px + `global_coat` 白大褂色）。
   - 内缩量必须用**平滑单调曲线**（`SHOULDER_FLAT=470` → `INSET_FULL_Y=660`，`INSET_REF_WIDTH=62`）—— 逐行按「袖子宽度比例」算会因宽度抖动产生锯齿。
   - 衣身取色**不能**取洞口右侧窄条（常落在描边/青边上 ⇒ 灰蓝块 + 横向条纹）⇒ 用全局白大褂色平铺。
5. **角度约定已标定并写进 docstring**：`rotate_rgba(ang)` 使方向 atan2 角减少 `ang` 度 ⇒ **`ang > 0` = 视觉逆时针**；画面左臂外抬用负角、右臂用正角；前臂向中线折叠用正肘角（+95~+145）。**IK 的 `angles_from_ik` 对「肘部移动后前臂指向腕目标」有偏差，折叠姿态直接用标定角更可靠。**

### 3.1 交付前自检抓到并修掉的「髋部虚线鬼影」（R158 内部修正）

第一次烘焙完成后逐帧放大检查，发现**每个抬手动作的髋部两侧都有一圈虚线残影**（原手臂轮廓被擦剩一半）。用像素差定位后确认根因：

- 手臂掩膜只含**肤色/袖色**像素，而**手的描边与手指间的暗线不在掩膜内**（洪水填充把暗线当阻隔）⇒ 摘掉手臂后原手轮廓残留成虚线。
- 原实现只擦 `ring_l / ring_r_` 两条窄带，手指轮廓的大部分像素漏网。
- 肉眼看到的"虚线"其实是描边外的**抗锯齿浅色晕**（lum≈175），只清 lum<130 的暗线核心清不掉它。

修法（三处，全部在 `restore_body` 内）：

1. **重建了大褂边缘的行** ⇒ 大褂外缘之外整段清成透明（大褂外缘本来就该是背景）。
2. **被跳过的那几行**（袖子已完全离开大褂，`edge` 越界而 `continue`）⇒ 只清「**紧贴手部皮肤 5 纹理 px 以内**」的暗线。实测几何：手的描边就画在皮肤外沿（离皮肤 0~4 px），而大褂门襟竖线离皮肤 ≥6 px ⇒ **半径 5 刚好能把两者分开，不误伤衣身**。
3. 亮度阈值放到 **lum<215**，把抗锯齿浅晕一并清掉。

**客观结果**（`cheer_heart_1`，髋部两侧带、lum<230 判据）：残留 **1743 → 467 px（−73%）**；同时衣身完好 —— 核心区青色饰条 **24587 → 24571（−0.07%）**，大褂门襟竖线（x=640）连续暗行 **112 → 110**。肉眼复核：虚线鬼影消失，大褂边缘与下摆无锯齿、无灰块。

> ⚠️ 踩坑记录：最初用「整列暗像素计数 ≥45% 高度」来识别大褂竖线，结果**袖子的外轮廓与手轮廓同列**，被判成竖线 ⇒ 鬼影清不掉；改成「只在手部盒行范围内统计」后又误伤了门襟线（连续暗行 112→80）。最终判据改为**几何距离**（离手部皮肤 ≤5 px），与内容无关，稳定。

### 6.2 关键 bug：点击路径从不调用 `applyPropsFor`

R156 引入道具系统后，`applyPropsFor(action)` 只在**状态机动作**路径里被调用；**点击反馈路径**（`startClickReaction` / `updateClickReaction`）从未调用 ⇒ **点击时爱心特效永远不会被挂载**，即使 manifest 里登记了 `props.scenes.cheer_heart`。

修复（`src/renderer.js`）：

```js
// startClickReaction 末尾
applyPropsFor(action);        // 点击开始 → 挂载该动作的场景道具 (比心的爱心)
// updateClickReaction 的 finished 分支
applyPropsFor(currentAction); // 点击结束 → 道具跟着回到当前动作的场景 (爱心退场)
```

**修复前后的客观对比**：修复后 `39_R158_runtime_verify.py` 实测爱心粉红像素从 **0 → 395**（阈值 60，R−G>80 颜色判据），且**串场 0 处**、退出后残留 0。

## 10. Mac 真机验收重点看项（`C2_Mac人工验收.command`）

5. 点到跳跃 → **有没有真的离地 + 双臂上扬**
6. 点到歪头 → **头是不是真的歪了**（17°，明显）
7. 盯住**大褂边缘**（抬手/举臂处）→ **有没有鬼影/锯齿/灰色块**
8. 点完动作结束 → **爱心特效有没有退干净**，别残留到待机
