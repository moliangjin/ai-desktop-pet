## 一、本轮改了什么

### P0-1 办公场景：双手没有真正操作键盘

#### 真根因不是"手的位置不对"，是 **z 序根本不成立**

渲染顺序固定为 **back 层道具 → 角色 → front 层道具**。R165 的桌面把台面画在 **back 层**，而角色的**大腿正好压在台面那条带上** ⇒ 台面被她的腿整片挡住，**键盘压根没地方出现**，用户看到的永远是"双手搭在腿上"。同时：

1. **根本没有键盘这个道具** ⇒ "手按键盘"在物理上不存在；
2. 笔记本**底座落在台面近沿**，与键盘抢位置 ⇒ 透视关系错乱。

#### 修法（4 处，全在几何层）

| # | 改动 | 说明 |
|---|---|---|
| ① | 角色帧在 `y=592` 以下**剪掉下半身** | 保留双手 + 腕带 ⇒ 台面从她腰部露出，角色读作"坐在桌后" |
| ② | **新增 `prop_keyboard.png`**（back 层） | 远沿 `y=566` / 近沿 `y=664`，`KB_FAR_X=(338,574)` / `KB_NEAR_X=(306,592)`，4 排键位 + 空格键；**分隔线加粗到 4~5 纹理 px**（200×240 下 1 纹理 px 只有 0.2 屏幕 px，细线会整条消失） |
| ③ | 笔记本**后移** | 盖板 `LID_QUAD` y428~596、基座 `LID_BASE_QUAD` y596~624 ⇒ **屏幕在后、键盘在前**，深度关系正确 |
| ④ | 台面**加深** | 远沿 556→**552**、近沿 668→**700**、前沿 `DESK_LIP_Y`=(700,732) ⇒ 200×240 下台面可见带达 21 屏幕 px |

> **为什么键盘必须画在 back 层**：角色层夹在 back 与 front 之间 ⇒ 无论怎么调道具的 x/y，手永远压在键盘上。键盘若拆成 back/front 两层，会被角色切成两半、碎成两截。

#### 打字动作

`work_1` 手指按下（press = 17 纹理 px）/ `work_2` 抬起 ⇒ **手部质心位移 10.2 纹理 px**（≈2.0 屏幕 px）。

#### 手部掩膜的三版踩坑（记录，避免重试）

| 版本 | 做法 | 后果 |
|---|---|---|
| v1 | 肤色 + 2px 暗环取手 | 手指之间的暗线被切成**碎虚线** |
| v2 | v1 + 补上边界描边 | 仍然糊边（描边没跟手一起搬） |
| **v3（最终）** | `_hand_region()` = **排除青色与白色**的实心掩膜（`~teal & ~white & opaque & dilate(sk,6)`），**上边界描边随手下移** | 手部整体平移、无线条断裂 ✅ |

另：`np.where(strip[:,:,None], ...)` 必须用（布尔掩膜形状不匹配会报 IndexError）；两个手的取样框**不能重叠**，否则第二次按压会把第一次的结果再搬一次。

### P0-2 睡眠场景：被子像光滑灰蓝色硬壳

#### 真根因

被子是**平涂色块 + 硬边**，没有任何高度/明暗层次 ⇒ 读作"盖在身上的塑料壳"；同时床的立板与腿落在 **200×240 窗口裁切线以下**（窗口底只到纹理 y≈735），所以"床几乎看不见"。

#### 修法

| # | 改动 | 说明 |
|---|---|---|
| ① | 被子改成**高度场 + Lambert 着色** | **形体 / 绗缝鼓包 / 折痕沟槽三层分开给权重** ⇒ 鼓包自动出高光凹陷、沟槽自动出"一侧受光亮边 + 另一侧柔和阴影" |
| ② | 配色由灰蓝改浅蓝 | 暗 **#7EA6D1** → 亮 **#E0EEFA**；菱形绗缝（旋转 32°）+ 顶部翻折被沿 + 边缘羽化（alpha blur 2.8 + 左沿淡出） |
| ③ | **床头立板做高做宽** | 上沿提到 `y=228`，`x0≈108` ⇒ 露出 90+ 屏幕 px 的木立板 |
| ④ | 床垫 + 木质床侧栏整体**上移 40 纹理 px** | 床垫 574~676、床侧栏 672~724 并加下横档 ⇒ 床架与床垫在 200×240 下真正可见 |
| ⑤ | 床整体**横向缩到 1000 并右移 8 px** | 满足生产布局算法的"道具零越界" |

## 二、附带修正：`42_R158_measure_report.py` 的报表口径（**不是**素材问题）

### 发现过程

复跑 `42_R158_measure_report.py` 时，`cheer_jump` 的面积中位数偏差报 **−15.19%**，超过 15% 门槛 ⇒ 假 FAIL。但：

- `git diff HEAD -- assets/character_R158/` 为**空** ⇒ 点击动作帧逐字节未变；
- 直接量 `cheer_jump_0/1/2.png` 的不透明像素 = **172721 / 212927 / 182192**，中位数 182192 与脚本输出一致；
- **在 HEAD 的独立 worktree（`c689e7b`）上跑同一个脚本，得到完全相同的数字** ⇒ 这是 **HEAD 自带的存量问题，与 R167 无关**。

### 真正的根因

`cheer_jump` 三帧是**故意纵向压扁**的（蓄力 0.80 / 腾空 1.0 / 落地 0.84）：

| 帧 | 面积 | 原始偏差 | 该帧 `scale_y` |
|---|---|---|---|
| `cheer_jump_0`（蓄力） | 172721 | **−19.60%** | 0.80 |
| `cheer_jump_1`（腾空） | 212927 | −0.88% | 1.00 |
| `cheer_jump_2`（落地） | 182192 | **−15.19%** | 0.84 |

中位数落在落地帧 182192，182192 / 214814 = **0.848**，与 `scale_y = 0.84` 几乎一致 ⇒ **没有额外的水平压缩**，只是合法的纵向压扁。

**node 单测 `r158_click_actions.test.js` 的 C1 早在 R165 就改成了归一化口径**（注释原文："旧口径直接拿面积比基准，于是把『合法的纵向压扁』误判成『整体压缩』"），**但 42 号报表脚本没有跟上** —— 而它的文档字符串却自称"口径与 tests/r158_click_actions.test.js 完全一致"。这是报表工具的 bug。

### 修法（阈值与公式都不放宽）

```
ratio = 中位帧面积 / (基准面积 × 该帧 scale_y)      # 与 node 单测 C1 同一公式
```

- 数据源与 node 单测完全相同：`assets/character_R158/bake_report.json`；
- 阈值仍是 **15%**，没有放宽；
- **保留原始未归一化偏差字段** `area_median_deviation_pct_raw`，供复核"压扁是不是设计内的"。

修正后：

| `cheer_wave` | 211501 | 1.00 | −1.54% | −1.54% | PASS |
| `cheer_hands_up` | 216138 | 1.00 | +0.62% | +0.62% | PASS |

## 四、遗留限制（如实声明，不虚报）

1. **办公场景角色下半身被剪掉**（`y>592`），读作"坐在桌后"，桌下只剩椅子底座 —— 这是为解决 z 序（大腿整片压住台面）所做的**取舍**，不是疏忽。
2. **被子的绗缝读作柔和不规则鼓包**，不是清晰的菱形格 —— 折中是刻意避开 v1 的"瓷砖感"硬格。
3. **200×240 窗口底部只到纹理 y≈735**，床体下部（腿）被裁切；床垫顶面约 90% 被角色挡住，床的存在主要靠 **床头立板 + 木梁 + 角腿 + 床垫正面带** 表达。
4. `sleep_loop` 用的是 R138 老帧 `sleep_loop_00_base.png`（头顶 y=265），而被子上沿轮廓按 R153 `sleep_breath_in.png`（头顶 y=330）量 ⇒ **肩背会从被子上沿探出**（已在 200×240 合成图上可见，属可接受范围，但如实登记）。
5. **屏幕相对键盘右置**：正面视角下，若把屏幕正对放在键盘后方，会被角色身体完全挡住；因此采用"屏幕在右后方"的常规插画约定。深度关系正确（屏幕基座 596~624 在键盘远沿 566 之后）。
6. 手指级"真比心"几何在 200×240 不可读；**180° 背面转身仍缺 R138 素材**（沿用 R165 登记，未在本轮范围内）。
