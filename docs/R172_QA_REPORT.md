## 二、根因分析：不是"少画了腿"，是图层归属错了

R167 的办公场景有一条写死在注释里的设计前提（`29_R156_pose_bake.py`）：

> 渲染顺序是 back 道具 → 角色 → front 道具。台面 (`prop_desk_surface`) 在 back 层，
> 而角色的**大腿正好压在台面带上** ⇒ 台面被她的腿整片挡住，键盘根本没法出现在她手下
> ⇒ 把 `CUT_Y=592` 以下的身体剪掉，台面就能从她腰部开始露出来。

R170 沿用了这套设计，所以用户看到的两个现象是**同一根因的两个后果**：
下半身被剪 + 电脑只能画成"背朝观众的笔记本盖板"（`LID_QUAD`）。

R172 的改法是**换图层归属**，不是继续在身体上做文章：

| | R167 / R170（修复前） | R172（修复后） |
|---|---|---|
| 底图 | `sleep_enter_01_sit`（跪坐，膝盖高抬，手搭膝盖） | `wake_up_01_sit_up`（**双腿下垂、靴子踩地**） |
| 地面行 | 1001（脚底被剪掉后仍写 1001） | 1001（整帧下移 76px 使脚底正好落在 1001） |
| 桌面 | back 层 `prop_desk_surface`（被大腿挡死 ⇒ 剪身体） | **画进角色帧内部**（PNG 内 z 序：身体→桌面→键盘→手→桌沿桌腿） |
| 键盘 | back 层 `prop_keyboard` | 画进角色帧内部，紧跟桌面 |
| 双手 | 角色帧里的腕带/手（剪身体时保留） | 角色帧内部，旋转成"手指向前"，压在键盘上 |
| 电脑 | `prop_desk` 上的笔记本**背板**（`LID_QUAD`） | 独立的 **3/4 透视显示器正面**，屏内画蓝白科技界面 |
| 座椅 | back 层 `prop_chair` | back 层 `prop_office_chair`（新画，靠背从肩/头两侧露出） |
| 场景 back/front | back: chair+desk_surface+keyboard / front: desk+screen_glow | back: `prop_office_chair` / front: `prop_office_monitor` |

因为桌面与角色同处一张 PNG（角色帧层），**桌面可以正确地遮住大腿，而小腿与靴子完整留在桌下** —— 这正是任务书要求的"桌面可以局部遮挡腿部，但不能把下半身直接删除"。

### 3.2 烘焙关键决策

- **手部处理**：坐姿底图 `wake_up_01_sit_up` 的两只手是"掌心朝下、手指朝外侧"的平摊手（实测腕点 L(375,558) / R(649,558)），原样放在键盘两端会读成"手摊在桌面上"。做法是**只抠手（肤色+描边）、不抠青色袖口**，绕腕点旋转 ±38°，再整体上抬 16px 盖住桌面远沿。
  - **踩过的坑**：第一版把袖口一起抠出来跟着手旋转 ⇒ 袖口歪 76°、与袖子脱节成一个孤立青色小块（A/B 实测确认），改为只抠手后解决。
  - **上抬的原因**：桌面远沿在 y=620，袖口在 614~646 ⇒ 袖口必被桌面遮住；手不上抬的话，手与袖子之间会出现一道可见的缝。
- **桌面**：台面梯形（远沿 y=620 窄、近沿 y=706 宽），桌沿 y=706~742，桌腿 x(268~312)/(848~892) 落到地面行 1001。桌面遮住大腿（y 620~706），小腿与靴子（y 706~1001）在桌下完整可见。
- **显示器**：屏幕四边形 `[(690,398),(872,440),(866,524),(700,550)]`（左侧近、右侧远的 3/4 透视），屏内内容在 360×300 矩形里绘制后用**单应变换**透视贴入四边形（标题栏 + 侧栏 + 8 行代码 + 状态块）。底座落在桌面远端。
- **椅子**：刻意**不画中柱与五星脚** —— 角色坐在椅子上时中柱正好落在两腿之间，第一版画了完整转椅，结果椅子底盘从两脚之间露出一坨灰色异物（真机截图复核确认）。
- **头部**：`work_1` 低头（旋转 +13°、下移 7px、左移 3px）、`work_2` 抬头（旋转 −5°、上移 3px、右移 7px）指向键盘/屏幕；使用坐姿专用权重场（颈保护圈下移到衣领，避免"下巴动了嘴没动"）。

### 3.3 顺带修掉的预览器 bug（重要，影响历史证据口径）

`45_R165_scene_preview.py` 的 `to_screen()` 把"地面行"当成了"纹理底行 1024"：

```
旧: y_bottom = sy + (TEX - ground_row) * scale      # ⇒ 整幅图比运行时上移 (ground_row - anchor.y*TEX)*scale
新: y_bottom = ground_y + (TEX - ground_row) * scale # ⇒ 地面行正好落在地面线, 与 sprite_layout.js 一致
```

- 200×240 下旧实现整幅**上移 15.58px**，256×256 下 20.10px；
- 已用**真实 Electron capturePage 帧**与修正后的预览逐像素比对确认：平均绝对差 3.03，内容行范围 82~236 vs 82~235 ⇒ **修正后的预览才是运行时的真实位置**；
- 同一份数学的副本在 `83_R170_scene_verify.py` 里也一并修正；
- **影响范围**：历史轮次的**预览图**证据（不是真实采集帧）此前是偏高 15.58px 的，详见已知限制 L5。

## 六、如实登记的已知限制

| # | 限制 | 事实依据 |
|---|---|---|
| **L1** | **双手没有真正收到键盘中央**。坐姿底图两腕间距实测 280 纹理 px，肩→腕臂长仅 227 px，手腕无法挪到角色中线附近；强行平移会让手与袖口脱节。键盘因此按实际手位画成宽键盘（x 344~692），双手落在键区两端，指尖已旋转成"向前"方向 | 90_ 烘焙器几何实测 + A5 的 ratio 0.664 |
| **L2** | **袖口被桌面远沿遮住**。袖口在 y 614~646，桌面远沿 y=620 ⇒ 袖口大半被盖住，前臂与桌沿的衔接在 200×240 下只剩 2~3 屏幕 px，读作"手臂伸到桌面上" | 90_ 几何 |
| **L3** | **显示器是"正面 3/4 的屏幕"**，不是物理正确的背面同侧视角。2D 插画里"正面坐姿 + 正对观众的显示器"只能这样表达"看得到屏幕内容" | 构图约束 |
