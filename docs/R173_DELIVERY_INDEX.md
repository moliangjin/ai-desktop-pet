## 三、本轮最关键的一件事：为什么 R172 怎么平移都改不对

**R172 的构图前提是错的，不是"少画了东西"。**

- 正面坐姿的角色 + 想让观众看到屏幕内容 ⇒ 屏幕必须朝观众 ⇒ **角色必然坐在屏幕背面**。
- 这是**几何矛盾**，平移手/桌子/显示器改不了（R172 自己把这条写进了 honest_limits，却仍按 PASS 交付）。
- 唯一出路是**换底图**：让角色本身是侧向（3/4）的，屏幕朝角色、观众从侧面斜看。
- 素材盘点确认 `sleep_enter_01_sit` 是**现有素材里唯一**的 3/4 坐姿（吃水果/睡眠/行走/站立全是正面或侧面站姿），且属于 R138 原始图集 ⇒ 角色外观零改动、无外部素材、无 i2i。

手部则采用**不拆手臂**的方案：原手留在身体帧（袖口朝向天然连贯）→ 桌面盖住原位 → 手的像素复制一份压在键盘之上 ⇒ 手掌不被键盘遮、衔接无假接缝、且不会在指尖留鬼影。

## 五、已知限制（如实登记，完整 9 条见 `docs/R173_QA_REPORT.md` 第五节）

### L1 屏幕内容在 200×240 下只有约 34×48 px
只能读出"有蓝白界面内容"，读不出具体文字。这是"从侧面斜看"的必然结果（透视压缩）—— 要看清内容就得让屏幕正对观众，而那正是 R172 被否掉的构图。**两条要求在 200×240 下存在物理冲突，本轮选了用户本轮明确要求的透视正确性。**

### L2 显示器仍是 2D 近似
屏幕四边形按"远侧边更矮"的透视画出，但角色帧本身是 2D 贴图、没有 3D 相机，无法解真单应。

### L3 桌偏高
桌面远沿压在腕点下方（手必须落在桌面上，而原坐姿的手腕高度就在那儿），读起来像高脚桌/吧台桌 + 高凳，画面里没有解释这个高度。

### L4 打字动作是手的整体位移 + 抬头/低头
不是逐键动画；200×240 下手指位移约 1.4 屏幕 px。

### L5 膝/大腿被桌面遮住
小腿与靴子完整可见 —— 沿用 R172 的"局部遮挡腿，不是删除"口径，但比正面构图遮得更多。

### L6 椅背只露出一条
画全椅子在 200×240 下会变成右边一个灰色柜子抢主角（R173 第一版画整椅 = 右下一个悬空灰罐）。

### L7 头部视线方向靠底图自带的 3/4 朝向 + 显示器位于画面左侧共同表达
没有做眼球偏航/头部偏航（2D 素材限制）；头部动作只是上下位移 + 轻微滚转。

### L8 `83_R170_scene_verify` 的 W3 预期 FAIL
"work 帧不得改动"与 R173 任务书直接冲突（本轮就是要改 work 帧），该脚本其余 12 项全部 PASS。

### L9 真机观感未确认
所有视觉结论都来自**真实 Electron 运行像素 + 逐帧目视复核**，但沙箱无法代替你在 Mac 上看最终观感 ⇒ `MAC_REAL_GUI_ACCEPTANCE = PENDING`。
