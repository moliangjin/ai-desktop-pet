## 一、本轮任务与 R172 的失败点

R173 任务书指出两个必须纠正的错误：

1. **显示器方向错误** —— 屏幕正面朝向观众，背对角色；要求改成合理的侧前方 3/4 视角（显示器正面朝向桌宠、角色视线朝向显示器、观众从侧面能看到部分屏幕内容、显示器/角色/桌面遵守统一透视），并明确「**不得让显示器正对观众，却让人物坐在显示器背面**」。
2. **双手被键盘和桌面遮挡** —— 要求键盘在桌面上、双手伸向键盘、手掌不被键盘整体遮住、手臂/手腕/手指衔接自然、打字时有可见的小幅动作、桌沿可以挡腿但不能挡正在打字的双手。

并要求「**禁止继续在错误的正面构图上反复平移手、桌子和显示器**」。

### 1.1 根因：R172 的构图前提本身是错的

R172 的 honest_limits 里其实已经写下了这句话：

> 「显示器是**正面 3/4 的屏幕**，不是物理正确的背面同侧视角 —— 2D 插画里正面坐姿 + 正对观众的显示器只能这样表达『看得到屏幕内容』。」

也就是说，R172 **知道**这个矛盾，却仍然按 PASS 交付了。根因在底图选择：

- 正面坐姿（`wake_up_01_sit_up`）的角色 + 想让观众看到屏幕内容 ⇒ 屏幕必须朝观众 ⇒ 角色必然在屏幕背面。
- 几何上无解：**正面角色 + 可见屏幕 = 自相矛盾**，无论怎么平移手/桌子/显示器都改不了。
- 唯一出路是**换底图**：让角色本身是侧向（3/4）的，屏幕朝角色、观众从侧面斜看。

### 1.2 现有素材里有没有 3/4 坐姿

素材盘点（`assets/character_R138/` 全量 + R153/R156/R172 派生）：

| 素材 | 姿态 | 能否做 3/4 办公 |
|---|---|---|
| `wake_up/wake_up_01_sit_up` | 正面坐姿，双腿下垂 | ❌ 正面（R172 用的就是这个） |
| `sleep_enter/sleep_enter_01_sit` | **真 3/4 坐姿**：膝盖与靴子朝画面左、脸也转向左 | ✅ **本轮采用** |
| `sleep_enter/02_lie` / `03_settled` | 躺卧 | ❌ |
| `idle/*`、`walk_*` | 站姿 | ❌ |
| `character_R156/eat_fruit_*` | 正面坐在小凳上 | ❌ |
| `character_R153/*` | 正面站姿表情/动作 | ❌ |

结论：`sleep_enter_01_sit` 是**唯一**可用的侧向坐姿，且它属于 R138 原始角色图集 ⇒ 角色外观（银白短发、冰蓝眼、白大褂+青色内衬）完全不变，不引入任何外部素材、不做 i2i。

## 二、R173 的改法

### 2.1 构图链路

```
角色(3/4 朝左) → 键盘(桌面远端) → 显示器(桌面更远端, 屏面朝右=面向角色)
      ↑ 视线              ↑ 双手压在上面              ↑ 观众从侧面看到被压缩的屏内容
```

三条要素全部落在**同一条朝画面左侧的链上**，共用同一套透视（桌面左端更远 ⇒ 更高；显示器远侧边更矮 ⇒ 上下边在近侧发散）。

### 2.2 关键几何（1024 纹理，最终空间，地面行 1001）

| 元素 | 几何 |
|---|---|
| 底图 | `character_R138/sleep_enter/sleep_enter_01_sit.png`（脚底 1002 ≈ 地面行 1001，无平移） |
| 桌面远沿 | (215,548) → (690,645)（左端更远更高） |
| 桌面近沿 | (165,662) → (640,757) |
| 桌沿厚度 | 近沿以下 30~34 px；桌腿 x158~186 / x632~662，落地面 1001 |
| 键盘四边形 | (330,566) (548,600) (532,656) (312,616) |
| 显示器屏幕四边形 | (195,395) (330,315) (372,630) (215,570)，远边 176px / 近边 318px（比 **1.804**） |
| 椅背 | (600,300) (790,322) (802,600) (610,590)，画在角色**之下**，只露右肩外侧 |
| 手腕 | L(405,556) / R(500,552)；袖口不参与旋转 |
| 打字动作 | work_1 手下压 7px + 头 dy −9/rot −2.5°；work_2 手 +1px + 头 dy +3/rot +1.5° |

### 2.3 手部图层关系（用户第 2 条的核心）

R172 的做法是「把手抠出来 → 旋转 → 贴回」，R173 不这么做，理由是：旋转会让手与袖口脱节。

R173 的做法：

1. **原手留在身体帧里**，袖口朝向完全不变（与身体里的白袖子天然连贯）；
2. 桌面画在身体之上 ⇒ 手的**原位**被桌面盖住（膝盖也被局部遮挡，但腿脚在桌下完整可见）；
3. 把手（肤色 + 描边，不含青色袖口）**复制一份**，画在**键盘之上** ⇒ 手掌不被键盘整体遮住，指尖落在键区。

因为"副本只做**向下**位移"，露出来的只是原手腕那几像素（与副本重叠、连成一只手），**不会在指尖留下鬼影**（R158 踩过的坑：搬手后原轮廓残留成虚线）。

### 2.4 为什么全部内嵌进角色帧

运行时道具是按 **action 整组挂载**的（`applyPropsFor`），不支持逐帧换道具。桌面/键盘/显示器/手要参与"打字微动作"，就必须内嵌进角色帧（PNG 内 z 序可控）：

```
地面阴影 → 椅子 → 角色身体 → 桌面 → 显示器 → 键盘 → 双手 → 桌沿桌腿
```

故 `props.scenes.work` 的 back/front 均为空数组。R172 的 `prop_office_chair` / `prop_office_monitor` **文件仍在磁盘、仍在 manifest 的 library 里**（历史成果可复审），只是 work 场景不再引用。
