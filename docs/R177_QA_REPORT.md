## 二、本地性格与心情系统

### 2.1 心情怎么判出来的（全部可复算，无随机）

`mood_engine.js` 用四个分数做比较，最高者胜；**平分时「平静」优先**（基准最稳）。

| 心情 | 分数公式 | 阈值 | 含义 |
|---|---|---|---|
| 平静 calm | 固定基准 | 0.6 | 其它心情都没超过它时 |
| 开心 happy | `交互次数 × 0.8`（3 分钟窗口） | 上限 1.6 | 刚被逗过 |
| 困倦 sleepy | `深夜(23:00~06:00) ? 1.2 : 0` + `清醒小时数 × 0.4` | 上限 2.0 | 深夜或久不睡 |
| 无聊 bored | `既无交互也无自主活动的分钟数 × 0.35` | 上限 1.8 | 好久没人理 |

情绪来源全部是**真实运行时事件**：用户交互次数（点击/菜单/拖拽）、自主活动切换、睡眠次数、清醒起点、本地时段。

### 2.2 心情怎么影响行为

| 调制 | 开心 | 平静 | 困倦 | 无聊 |
|---|---|---|---|---|
| 自主决策间隔系数 | **0.7**（更勤快） | 1.0 | **1.5**（更迟钝） | **0.6**（最勤快） |
| gesture 权重 | 1.6 | 1.0 | 0.6 | 1.5 |
| walk 权重 | 1.3 | 1.0 | 0.5 | 1.4 |
| sit 权重 | 0.8 | 1.0 | 1.4 | 0.6 |
| doze 权重 | 0.5 | 1.0 | **2.2** | 0.5 |
| work 权重 | 1.0 | 1.0 | 0.4 | 1.2 |
| eat_fruit 权重 | 1.2 | 1.0 | 0.6 | 1.3 |
| sleep 权重 | 0.5 | 1.0 | **2.0** | 0.6 |
| 点击动作池权重 | cheer_heart 1.8 / cheer_wave 1.5 … | 全部 1.0 | cheer_jump **0.3** / cheer_clap 0.5 … | cheer_tilt 1.2 … |

> **心情永远不会静默吞掉点击反馈。** 心情对"互动反馈"的影响**只用权重表达**
> （困倦 ⇒ 偏轻量动作），不做"点了没反应"。
> 原因：R156/R162 有一条既有产品不变量 ——「点击必须产生可见反馈」
> （e2e 的 TG2 / TH5 / TI1_1 / TI1_2 / TI1_24 五组判据都在守它）。
> 本轮第一版曾设 `sleepy_suppress_click = true`（夜里点她没反应），
> **被 e2e 当场判 FAIL 抓出来**（7 项 FAIL 全部同源），现已改回默认关闭。
> 该开关仍保留在配置里（显式开启才生效），但默认不启用。
| 是否禁用点击反馈 | 否 | 否 | 否 | 否 |

> **为什么把"平静"的权重全设成 1.0**：心情系统是**加装**在既有行为系统之上的；平静时所有系数必须是 1.0，这样"心情系统不改变原有行为"可以被客观验证（单测 `M9` 逐项断言）。

### 2.3 精力

精力随清醒时长缓慢下降（每小时 −0.05），睡一觉恢复为 1.0，并记一次 `sleepCount`。

## 三、桌宠控制菜单

### 3.1 菜单结构（`src/menu_template.js`，纯模块）

```
心情：开心          ← 只读（enabled: false），是信息不是命令
────────────
睡觉                → command('sleep')
醒来                → command('wake')
坐沙发休息          → command('sit')
电脑办公            → command('work')
吃水果              → command('eat_fruit')
随机可爱动作        → command('gesture')
────────────
设置…               → 打开设置面板
退出桌宠            → app.quit()
```

**菜单里没有任何调试项**（单测 `C4` 断言可点击项集合 ⊆ 上述 9 项，并扫描 label 不含 `debug/测试/演示/状态/log/日志` 字样）。

### 3.2 「必须使用现有正式行为系统，不允许只播放演示图片」怎么保证的

`BehaviorEngine.command(kind)` 调用的是**自主决策用的同一批内部方法**：

| 命令 | 调用 | 与自主决策的关系 |
|---|---|---|
| 睡觉 | `_enterSleep()` | 完全相同 |
| 醒来 | `wakeUpByUser()` | 完全相同（走 wake_up 一次性动画，不瞬移站姿） |
| 坐沙发休息 | `_startSit()` | 完全相同 |
| 电脑办公 | `_startWork()` | 完全相同 |
| 吃水果 | `_startEatFruit()` | 完全相同 |
| 随机可爱动作 | `_startGesture()` | 完全相同 |

⇒ 状态转移、冷却、计时器、**道具挂载**、动作结束后的回落，全部复用，不存在旁路。

与自主决策只差两点（且都是**用户要求**的）：
1. **不受同类冷却限制** —— 用户明确要求"坐沙发休息"，就不该因为"刚坐过"而不响应；
2. **接管当前排程** —— 清掉待触发的行为计时器，否则会被下一次自主决策立刻覆盖。

**客观证据（不是声明）**：

- 单测 `C6/C7`：命令后状态机真的切到 `WORK / SIT / EAT_FRUIT / DOZE / GESTURE / SLEEP_ENTER / WAKE_UP`，且动作真的下发给渲染器；
- 单测 `C11`：手动命令与自主决策产生的状态转移**原因完全一致**（`idle-decision`）⇒ 同一套内部路径；
- 单测 `C9`：命令后旧计时器被清掉、换成该行为自己的状态计时器 ⇒ 确实接管排程；
- 单测 `C10`：办公冷却 60s，但连续两次手动办公都成功 ⇒ 确实不受同类冷却限制；
- **真实 Electron 实跑**：菜单命令"电脑办公" → `MENU command=work ok=true state=WORK` + 状态转移记录 `IDLE -> WORK` + 渲染器 `set-action work applied=true`；"吃水果" → 道具真的挂载 `prop_stool,prop_fruit_table`；"睡觉" → `prop_bed,prop_moon,prop_quilt`。

### 3.3 右键不能误触发拖拽（这是个真实的坑）

改造前 `sprite_.on('pointerdown')` **没有按键过滤** —— 右键会走进拖拽分支（角色被"拖走"）并可能触发点击反馈。

本轮修法：
- Pixi 的 `pointerdown` 里取按键号（`ev.button`，取不到退回 `ev.data.originalEvent.button`）：**只有 button===0 才允许开始拖拽**；button===2 直接请求弹菜单并 `preventDefault`；其它按键忽略；
- canvas 上再挂一层 DOM `contextmenu` 监听：永远 `preventDefault`（挡掉 WebView 默认菜单），并且**只有点在角色身上**才弹桌宠菜单（透明区不弹）；
- 400ms 去重，避免同一次右键弹两次。

## 四、设置面板

独立 BrowserWindow（340×486，`titleBarStyle: hiddenInset`），**不叠在桌宠上、不污染桌宠外观、没有任何调试项**。

| 设置项 | 取值 | 作用路径 |
|---|---|---|
| 桌宠大小 | 0.6 ~ 1.6（步进 0.05） | 窗口尺寸 + 渲染画布同步重建（保窗口中心） |
| 自主活动频率 | 低 / 正常 / 高 | 决策间隔 ×1.8 / ×1.0 / ×0.6；活动权重 ×0.6 / ×1.0 / ×1.4 |

| 开机自动启动 | 开 / 关 | `app.setLoginItemSettings`（**仅 macOS / Windows 提供**，Linux 开关置灰并写明原因） |

面板自己不碰磁盘、不自己改引擎：所有修改都走 `settings-set` IPC → `applySettingsPatch` → 落盘 + 应用到运行时，面板再拿回**权威值**刷新显示。

## 七、本轮发现并修掉的 3 个真 bug（都是测试逼出来的，不是靠通读代码）

1. **心情恢复永远是「平静」**
   `mood_engine.js` 里 `MOODS[st.mood]` 用**小写值**去查**大写键**的对象 ⇒ 恒为 `undefined` ⇒ 恢复时永远回退平静。
   单测 `M12` 抓到。修法：新增 `MOOD_VALUES = Object.values(MOODS)` 并改用它判定。
   ⇒ **如果不写这个测试，"重启后恢复心情"这一条会在用户手里静默失效。**

2. **「睡眠频率」设置完全不起作用**
   `rateEffects()` 返回的键是 `sleep_weight`，而 `main.js` 读的是 `fx.sleep` ⇒ `undefined` ⇒ `applyConfig` 忽略非数字 ⇒ `sleep_weight_scale` 永远是 1.0。
   单测 `S11` 抓到。修法：`main.js` 改读 `fx.sleep_weight`。

3. **`--user-data-dir` 被 Electron 静默忽略**
   写成 `--user-data-dir <path>`（两个独立参数）时，Chromium 的命令行解析只认 `--switch=value` ⇒ 设置被写到了**默认目录** `~/Library/Application Support/Electron`，测试"隔离目录"的前提直接失效（还污染了用户目录）。
   第一次真跑时由判据 `A1` 抓到。修法：脚本与 e2e 一律使用 `--user-data-dir=<path>` 形式。

> 第 3 条还牵出一个**真实的产品级隐患**：`R147_e2e_test.sh` 原来直接用默认 userData 目录，
> 于是**用户自己改过的设置会让 e2e 判据崩掉**（`pet_scale≠1` → 采集帧尺寸与判据里的 200×240 对不上 → 判据脚本直接抛异常；
> `click_feedback=false` → 点击反馈被禁用 → "点击池随机性"类判据必然 FAIL）。
> 本轮已把 e2e 改成**每次用临时 user-data-dir**（`R147_e2e_test.sh` 4 处启动全部隔离），
> 这样 e2e 的前置条件恒定，不再受用户设置或历史残留影响。

## 八、如实登记的已知限制

1. **「开心」判定很灵敏**：一次点击交互即进入开心（0.8 > 0.6 的平静基准）。这是刻意的（点一下就是一次互动），但体感上可能"太容易开心"。
2. **深夜困倦优先级高于开心**：23:00~06:00 困倦分数 1.2 > 开心 0.8 ⇒ 夜里她整体表现得很困（动作更少、更爱打盹、点击反馈偏轻量），但**点击一定还有反馈**。符合规则，**真机体感需要你确认**。
3. **心情不改变"点击有没有反馈"，只改变"反馈是哪一个动作"** —— 困倦时更可能出轻量动作（cheer_jump 权重 0.3、cheer_clap 0.5），不会不响应。这是本轮**刻意**的选择（守住 R156/R162 的「点击必须有可见反馈」不变量）；如果你想要"困倦时干脆不响应"，说一声，把 `sleepy_suppress_click` 打开即可。
4. **桌宠大小是"整体放大"**：实现方式是放大窗口 + 重建画布，属于**位图放大**而不是重绘更高分辨率 ⇒ 1.6× 时边缘会略有柔化。
5. **开机自动启动**走 Electron 的 `setLoginItemSettings`；macOS 首次勾选后可能需要在「系统设置 → 通用 → 登录项」里确认一次。
6. **设置面板的 UI 观感、菜单在真实鼠标下的位置与手感、右键与拖拽的实际隔离效果**，都还需要你的 Mac 真机确认。
